# 小莫划船机 App · 产品需求文档(PRD)

> 版本 v0.3(高保真原型定稿) · 2026-05-17
> 配套交付:`prototype/index.html`(可点击高保真原型)、`docs/design-spec.md`(设计规范)、`docs/flow.md`(流程图)

---

## 1. 背景与目标

用户购入二手「小莫」智能划船机(母公司 **Anytum**,品牌「莫比健身」,Google Play 包名 `com.anytum.mobirowinglite`)。原厂 App 已停服(登录不上、商店下架),设备本身完好。目标:**自建一个替代 App,恢复"连接划船机、看实时数据、记录训练"的核心价值,并做成真正能长期使用的训练 App。**

- 设备蓝牙名固定 `AT-R79517`,私有协议(非标准 FTMS):数据走 `0xFFE0/0xFFE4` notify,13 字节帧 `AB 04 01 09 00 64 01 00 00 [间隔hi lo] [脉冲计数hi lo]`,每飞轮脉冲一包。
- 划船机**无屏幕、无绝对参照**:所有训练指标由脉冲流换算(Concept2 模型),距离 = 脉冲 × 可调系数(默认 0.45 m/脉冲)。
- 协议已破、物理引擎可用(冒烟版已上线):`lib/ble/anytum_rower.dart`、`lib/ble/rowing_metrics.dart`。

## 2. 目标用户

- **主用户**:房总(设备拥有者),日常划船训练、看记录与趋势。
- **家庭多用户**:同一台划船机、同一台手机,家人各自独立的训练档案与记录(本地多用户,无需账号系统)。
- 技术水平不限:连接过程必须**零操作自动完成**,像 Keep 跳绳一样"按开始 → 自动连 → 开练"。

## 3. 范围

### 3.1 本期范围(高保真原型已覆盖)

| 模块 | 说明 |
|---|---|
| 启动 / 自动连接 | 启动页「开始划船」→ 自动扫描连接(零点击)→ 连接成功 3-2-1 倒计时 → 进入仪表盘,**连上后才从 0 计时计数** |
| 训练目标设置 | 自由划 / 定距 / 定时 / 定卡 / 间歇 / 目标配速(配速船);收藏常用训练 |
| 实时训练仪表盘 | 配速(/500m)、桨频 SPM、功率 W、距离 m、桨数、时间、卡路里、心率;**每 500m 分段表**;结束保存 |
| 原始调试视图 | GATT 服务树 + 实时 13 字节帧日志(手机单栏可滚) |
| 训练记录列表 | 按日分组的历史记录,本周汇总,迷你曲线;列表 / 趋势分段切换 |
| 趋势 & 个人最佳 | 周期切换、每周距离柱状、平均配速趋势、连续打卡、各距离 PR |
| 单次记录详情 | 距离/时长 + 平均/峰值统计 + 配速/心率曲线 + 分段明细 + 分享/删除 |
| 我的 / 多用户 | 个人档案、累计统计、切换/添加用户、心率设备、训练标定入口 |
| 训练标定 | 米/脉冲、功率系数 k、抓水阈值滑杆;心率设备(标准 BLE 0x180D) |
| 边界 / 空状态 | 蓝牙未开启、连接失败重试、心率信号弱、无训练记录 |

### 3.2 明确不做(订阅内容型,自建机无意义)

教练实景视频课、游戏化关卡、真实航道路线、VR、多人在线竞速、付费挑战、大规模社交排行榜。社交仅保留"一家人多用户"。

## 4. 关键功能需求

### 4.1 连接(零点击,Keep 跳绳式)

- 启动页主操作 = 大按钮「开始划船」;次要入口「选择训练目标」;兜底「手动选择蓝牙设备」。
- 点「开始划船」后进入**自动连接中**:脉冲动画 + 文案自动流转(扫描中 → 已发现 AT-R79517 → 建立连接),提示"拉一下手柄唤醒",仅「取消」可中断,**中途无任何点击**。
- 连接成功 → **连接成功页 3-2-1 倒计时** → 进入仪表盘。
- 设备名匹配 `AT-R79517` 或已记住设备自动连;首次握手常瞬时失败,需自动重试(参考现有 8 次重试)。
- **计时计数规则:连接成功后才从 0 开始**;墙钟计时,停桨休息不清零、不暂停(由指标引擎 `elapsed` 决定)。

### 4.2 训练目标

- 6 种模式单选,选中后参数面板实时切换对应档位(定距→距离档、定时→时间档、定卡→卡路里档、间歇→方案档、目标配速→配速档);自由划无参数。
- 「开始训练」按钮文案随模式/档位实时变化(如「开始训练 · 定距 2000m」)。
- 收藏的训练:一键载入常用配置(如 2000m 计时赛、5×500m 间歇、30min UT2)。

### 4.3 指标与记录

- 指标全部来自 `rowing_metrics.dart`(Concept2:功率 = k·v³;滚动窗口测速;抓水状态机)。距离 = 脉冲 × 米/脉冲(默认 0.45)。
- 卡路里为**无参照估算值**(基于功率与时长),UI 不暗示其精确;体重字段为后续提高估算锚点预留。
- 每次训练存一条记录:开始时间、模式、距离、时长、桨数、平均/峰值配速·桨频·功率、卡路里、心率(可缺失)、**每 500m 分段**。
- **数据自洽要求**:同一次训练在仪表盘(进行中)、详情(完成)、列表、分段表、原始日志间数字必须一致。

### 4.4 心率(可选第二 BLE 设备)

- 标准 BLE 心率服务 `0x180D / 0x2A37`(`lib/ble/heart_rate.dart`)。目标设备 Xiaomi Watch S4 Sport 蓝牙心率广播;通用心率带(Polar/Magene 等)亦可。
- 实时显示 + 记录;**>5s 无更新标"信号弱"**,掉线时训练照常记录、恢复自动续上,该次心率字段标记"部分缺失"。

### 4.5 多用户与存储

- 本地多用户:每人独立记录/档案,无账号系统,本地切换。
- **本地优先,先不联网**:记录全部本地存储、离线可用;数据层须预留"上传/云端同步"接口,不写死。存储须移出 build 目录(Android app sandbox + SQLite/sqflite)。

### 4.6 边界与空状态(开发必须实现)

| 状态 | 行为 |
|---|---|
| 蓝牙未开启 | 顶部橙 banner,「开始划船」禁用,提供去系统蓝牙设置 / 重新检测 |
| 连接失败(重试 N 次后) | 失败页:重试连接 / 手动选设备 / 返回 |
| 心率信号弱 | 心率区灰显"--",标"⚠ 信号弱 >5s 无数据",仪表盘其余照常 |
| 无训练记录 | 空状态插画 + "开始第一次训练"引导 |

## 5. 非功能需求

- 离线可用;Android 出品(用户主力机 Xiaomi 17 Pro);Windows 桌面用于探测/调试(同一套 `universal_ble`,不换 flutter_blue_plus)。
- 单实例锁:防多实例抢蓝牙(已实现命名互斥量)。
- 手机竖屏适配:目标机 Xiaomi 17 Pro 6.3″ 1220×2656(≈19.6:9),设计基准逻辑宽 412;响应式,App 全屏铺满。
- 性能:实时帧 ~13ms/包级别刷新不卡;仪表盘每秒至少刷新一次(停桨也走表)。

## 6. 验收标准(关键)

1. 开机后点「开始划船」,无任何额外点击即可完成连接并进入仪表盘;计时计数从 0 起。
2. 训练目标 6 模式可切,参数面板与开始按钮文案联动正确。
3. 一次训练结束后,记录列表 / 详情 / 分段 / 趋势 PR 数据一致且合理。
4. 心率设备可选接入,断连有"信号弱"提示且不影响其余记录。
5. 四个边界/空状态均有对应界面与引导。
6. 多用户切换后看到各自独立记录。

## 7. 假设与待确认

- Xiaomi Watch S4 Sport 蓝牙心率广播走标准 0x180D(官方称兼容 Garmin/码表)——**待真机验证**;不行则退路通用心率带。
- 米/脉冲 0.45 为自洽经验值,无绝对参照;有参照时通过标定页调整。
- 间歇/目标配速的具体训练逻辑(组间休息提示、配速船偏差展示)细节在实现期细化。

## 8. 里程碑

- ✅ 冒烟版:协议打通 + 物理引擎 + 仪表盘 + 稳定连接(已在 GitHub)。
- ✅ 高保真原型定稿:本 PRD + 设计规范 + 流程图 + 可点击原型。
- ⏭ Flutter 实现:启动/自动连接/倒计时 → 训练目标 → 仪表盘+分段 → 记录/趋势/详情 → 多用户/标定 → 边界态。
